### 1.6 Keys

キーの割り当て。**割り当てられるのはアクションの表（`src/actions.rs`）の行すべて**（RFN01-114、2026-11-05）。分類はメニューの分類（ファイル・編集・挿入・レイアウト・表示・実行・ヘルプ）＋本文の操作・Terminal・左ペイン・Quick Draft。コピー・貼り付け・全選択・倍率は固定のキー。**保存は設定ファイル**（`shortcut-bindings`、操作のIDで書く。v=5）。

修飾キーなしの F10 はメニューを開く固定キー。Ctrl+F10 は割り当てられる。Ctrl+0 は既定倍率に戻す固定キー。Ctrl+Shift+W は Terminal のタブを閉じる。文書のタブを閉じるキーは `file.close-tab` の割り当てで決まる。

### 設定の識別と適用範囲

| 設定のまとまり | 項目と型 | 適用範囲・依存関係 |
| -- | -- | -- |
| General | 言語（選択肢）、既定倍率（%）、読み上げの声（音声ID）と速度（倍率） | アプリ共通。既定倍率と、現在のTABの倍率は別に扱う |

Editor と Terminal の外観設定は、背景とフォントのカード、フォントの選択行、スライダーと数値入力を備えた透過の行を共用する（RFN01-142）。Editor の背景カードでは書字方向別の色と、共通のランダム背景・透過を扱う。Text のカードでは本文・各見出し・コードのフォントを設定する。

Editor の書字方向別データは、現行の保存では各方向に数値・フラグ56枠、色16枠、書体8枠を持つ。保存キー数をそのまま検索候補数にしない。縦書きが継承中でも固有値を保持し、適用値は Text・Layout・Page の規則で解決する。装飾・折り返し・壁紙などの有効条件も、保存値から分けて扱う。

### 一覧で区別するデータ

| データ | 識別・検索の扱い |
| -- | -- |
| キー割り当て | `actions.rs` の操作IDを使う。Keysの操作行を設定定義へ再登録しない |

| プリセット | Editor・Terminal・Keys の設定値のスナップショット。設定の定義を複製せず、保存・適用する値の範囲を現行の分類と照合する |

### 設定の定義と表示先

* 共通定義は設定ID、書字方向と継承の種類、日英名と検索語、表示先の対応を持つ。設定値の型、既定値、検証、保存は既存の各設定の実装を使う。Slint は検索語を持たず、表示する行や欄ごとに表示先を指定する。
* 一つの保存キーに複数項目がある例は Terminal 外観。複数キーが一つの画面上の設定を構成する例は壁紙。設定項目と保存キーを一対一に固定しない。
* Terminal のプロファイル、動作、各 Panel の外観は表示先を分ける。Terminal Panel 外観は Editor にあり、その外観の設定が一致したときだけ検索結果に表示する。複数の設定を同じ部品で編集する外観・壁紙などでは、対象の部品をまとめて表示する。
* 保存する値が設定一覧・複合レコード・管理データ・作業状態・設定画面外のいずれかに分類されることを回帰テストで確認する。JSONへの移行は別件。

## 1.10 パレットで指定する設定の単位

パレットの1候補は、名前から「何を設定するか」「どの対象に効くか」が分かる単位にする。General や Editor のようなカテゴリ名は候補を区別する補助に使う。検索候補、設定データ上の値、選択後に見える欄は、それぞれ別の単位で扱える。

| 対象 | パレットの候補例 | 選んだ先 |
| -- | -- | -- |
| 単独で意味が分かる設定 | 表示言語、ルビ記法のオン／オフ | 該当する設定 |
| 書体など、対象別に調整する設定 | 横書きの本文フォント、横書きの H1 フォント、横書きの H2 フォント | 指定した対象の設定。たとえば H1 を開いた先では H1 のフォント、サイズ、色を一緒に確認できる |
| Terminal プロファイル | WSL のプロファイル設定、PowerShell のプロファイル設定 | 指定したプロファイルの名前・実行ファイル・引数・開始フォルダなどを一緒に編集する |
| Editor の単語チェックモード | 「作品A」の単語チェック設定、「作品B」の単語チェック設定 | 指定したモードの名前と、そのモードに属する語群を編集する |

### グループに含める値

| グループ | 含めるもの | 別の候補として扱うもの |
| -- | -- | -- |
| Terminal のプロファイル1件 | 名前、実行ファイル、引数、開始フォルダ、既定にする操作 | 他のプロファイル、Terminal の外観、貼り付け確認などの全体設定 |

Terminal のプロファイル設定では登録済みプロファイルを順番に一覧表示し、↑↓で選択行を移動する。追加・複製・WSL プロファイルの追加は編集欄に下書きを作り、「適用」で登録する。登録済みのディストリビューションを選んだ場合は既存プロファイルを開く。未インストールの実行ファイルやディストリビューションは起動候補から外し、設定済みのプロファイルは編集できる。

設定には利用できない理由も表示する。既定プロファイルが利用できない間は起動時だけ代替を使い、設定には既定の ID を保持する。起動や切り替えで明示選択したプロファイルが利用できなくなった場合は理由を表示し、現在のセッションを維持する。
| Editor の単語チェックモード1件 | モード名、所属する語群。語群ごとに名前、色または色なし、登録語と覚え書きがある。選んだモードを開いて、その中から語群を選ぶ | 他のモード、現在のTABで使うモードの切り替え。切り替えは既存の操作候補 |
| 本文または見出し1種の編集欄 | 同じ書字方向・対象のフォント、サイズ、文字色、装飾。フォント・サイズ・色は個別に検索でき、同じ編集欄を開く | 別の見出しレベル、別の書字方向、コード用フォント |

ソース／ライブプレビューの切り替えも Editor のモードだが、現行はTABの状態で、設定値は主に書字方向別に持つ。現行データを使う案では、パレットの設定候補は横書き／縦書きの設定を指す。ソースとライブプレビューへの切り替えは既存の操作候補で扱う。

### パレットが読むデータ

* **設定項目**は `SettingId`、日英の `Title`、別名を持つ。個別の値を指す。画面の行番号や表示順はIDに含めない。
* **設定グループ**は `GroupId`、日英の `Title`、構成項目、表示先を持つ。たとえば H1 のフォント・サイズ・色は同じ編集グループを参照できる。WSL の実行ファイルや引数は WSL グループの構成項目で、パレットではグループの候補を出す。
* **パレット候補**は `Title`、検索語、遷移先（個別の `SettingId` または `GroupId`）を公開する。個別候補は項目のTitleを、グループ候補はグループのTitleを使う。グループ内の項目名は検索語に含められる。候補を選ぶとIDで開き、Titleで検索し直さない。
* プロファイルと単語チェックモードのグループは登録データから作る。Titleには現在の名前を使う。単語チェックモードは既存の `WordMode.id` で指定する。Terminal プロファイルも固定IDを持つ。候補の選択時はIDで現在のプロファイルを開く。名前変更や並べ替えでIDを保持し、追加・複製には新しいIDを割り当てる。保存では従来の `terminal.shell.N` と並べて `terminal.profile-id.N` にIDを記録し、次のIDを `terminal.profile-next-id` に保存する。読み込みには対応するプロファイルIDが必要。N は保存位置であり、候補の識別には使わない。

### 選択時の動作

ルビ記法、行番号、Terminalの終了確認など、単独のオン／オフ設定はパレットに現在値を出し、選択すると既存の更新経路で切り替える。色・数値・選択肢・スライダーや、設定グループの候補は編集画面を開く。本文の太字など、関連値とまとめて調整する項目は編集画面で切り替える。自動退避はオフにすると作業コピーを削除するため、設定画面に効果を表示してそこで切り替える。

例として、`WSL 引数` で探すと「WSL のプロファイル設定」を開く。`横書き H1 フォント` で探すと「横書きの H1 フォント」を開き、同じ H1 のサイズと文字色も確認できる。

### 4.1 前提の言葉

前提は次の言葉の組み合わせで書かれている。**「対象」は、メニューを開いたとき（キーなら押したとき）に前にあったペインとTAB**。

| 言葉 | 意味（コードでの名前） |
| -- | -- |

| 上段の本文 | 本文を出していて、下段のEditor Panelではない（`main`） |

| シェルが動いている | 対象のシェルが終わっていない（`running`） |
| 選択がある | 本文またはTerminalで字を選んでいる（`selected`） |
| 入力欄にいる | 検索欄などの入力欄にキーボードがある（`field`） |
| 下段のEditor Panel | 対象が下段のEditor Panel（`is_panel`） |

### 4.2 アクションごとの前提

Git Repositoryの比較には表示中の差分、ブロック操作には選択した差分とブロック、二点比較には対象のコミットIDと設定済みの比較元が必要。実行時に表示対象を照合し、インデックスを変更する前にGitの状態も検証する。

Gitのファイル更新を待つ間に編集した原稿と復旧コピーは保持する。破棄が了承された文書は、操作が成功し、了承後の編集も保存先の変更もなければ読み直す。Hard Resetは実行時に未追跡・無視対象と衝突する場合に中止する。Stashの適用は選択時のオブジェクトIDを使う。DropとPop後の削除は、Gitの参照ロックの中で選択した行を照合して更新する。対象が替わった場合、識別が曖昧な場合、または安全な削除に対応していない参照形式では、削除を中止する。Popで適用だけが済んだ場合はその旨を表示する。

Stash AllのUndoとPopのRedoは、対応する操作で作成したStashを履歴に記録し、その行が現在も先頭にある場合だけ適用・削除する。作成した行を特定できなければ、削除を伴う履歴操作は使えない。

Worktreeを開く操作では対象のパス・現在のWorkspace・同じリポジトリに属することを照合する。新規作成では元のWorktreeとコミットID、入力された作成先と新しいブランチ名を保持し、Gitの実行前に再確認する。

リポジトリ一覧は左ペインに表示する。選択行を開く操作は、一覧を表示中でGit操作が実行中でないときに使える。パレットを開いたときの行と所属先を保持し、実行時に登録先とリポジトリのルートを再確認する。現在とは別のWorkspaceを開く場合は、切り替え先と開いているタブを閉じることを必ず確認する。

登録解除は一覧のボタン・割り当てキー・パレットで共通のアクションを使う。行の登録IDと所属先を保持し、確認の前後で台帳を照合する。Gitやパスを開けない行にも適用できる。

Mergeの解消（RFN01-138）は、表示中のリポジトリ・進行中のMerge・選択ファイルを照合する。編集には作業ファイル、削除の採用には片側が削除したファイル、続行には未解決パスがないことが必要。Stageと削除では対象ファイル、続行と中止では対象リポジトリの未保存文書を先に保存する。実行時にGitの状態も読み直す。

「いつも」は前提なし。
