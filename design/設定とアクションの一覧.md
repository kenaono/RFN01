## 4. アクションが実行できる前提（2026-11-05）

書き手の求め（2026-11-05）：アクションには実行できる前提がある。それも整理しておく。

元データはタイトルバーのメニューを組む処理（`src/menu_commands.rs`の`build`）の、行ごとの「押せる条件」。ペインの⋮・右クリック・書式のボタンも同じ条件を使う（`text_state`を共有）。

### 4.1 前提の言葉

前提は次の言葉の組み合わせで書かれている。**「対象」は、メニューを開いたとき（キーなら押したとき）に前にあったペインとTAB**。

| 言葉 | 意味（コードでの名前） |
| -- | -- |
| 本文を出している | 対象のTABが文書で、設定のTAB・Terminal・「新しいTAB」（何を開くかを訊くTAB）ではない（`text`） |
| 書き換えられる | 本文を出していて、Viewer・ReadOnlyでなく、文書が読み取り専用でなく、入力欄にいない（`editable`） |
| 上段の本文 | 本文を出していて、下段のEditor Panelではない（`main`） |
| ファイルがある | 文書が保存先のファイルを持つ（無題ではない）（`path`） |
| Terminal | 対象が上段のTerminalか下段のTerminal Panel（`terminal`） |
| シェルが動いている | 対象のシェルが終わっていない（`running`） |
| 選択がある | 本文またはTerminalで字を選んでいる（`selected`） |
| 入力欄にいる | 検索欄などの入力欄にキーボードがある（`field`） |
| 下段のEditor Panel | 対象が下段のEditor Panel（`is_panel`） |

### 4.3 前提の扱い（入口ごとの違い）

| 入口 | 前提を満たさないとき |
| -- | -- |
| タイトルバーのメニュー・⋮・右クリック | 行を灰色にして押せない。子が全部灰色なら親も灰色 |
| コマンドパレット | **出さない**（メニューで押せない行は並べない） |
| キー | **確かめずに実行先へ渡す**。実行先がそれぞれ同じ判定を持っていて、満たさなければ何もしない（`run_shortcut`） |
| 書式のツールバー・パレット | メニューと同じ判定（`text_state`）で灰色 |

### 4.4 メモ（前提）

* **前提が入口ごとに書かれている**：メニューは`build`の行ごとに、キーは実行先ごとに、パレットはメニューの結果を借りて判定している。アクションの表（RFN01-114）を作るなら、前提もアクションの側に1つずつ持たせ、入口はそれを読むだけにしたい。
* **キーは前提を確かめない**：前提を満たさないキーを押すと、何も起きない（知らせも無い）。2026-11-05、メニューの判定をそのまま使って知らせる案を試したが、メニュー全体を組むのに1回36ミリ秒かかり、キーのたびには使えなかった。前提をアクションの側に持たせる作業（RFN01-114）でまとめて直す。
* **「保存」と「名前を付けて保存」の前提の違いは意図どおり**：ReadOnlyモードでは上書き保存を断り、別名で保存させる（2026-09-15の仕様）。
