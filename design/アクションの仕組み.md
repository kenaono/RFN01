# アクションの仕組み（設計資料）

**この資料の位置づけ**：RFN Editの「アクション（操作）」を、どう名指しし、いつ実行してよいかをどう決め、どの入口からどう走らせるかの決まり。RFN01-66（2026-11-05、書き手と合意）で作り直した構造を書く。アクションと設定の**一覧**は [設定とアクションの一覧.md](設定とアクションの一覧.md)、こちらは**仕組み**。

**更新の決まり**：アクションの名指し・前提・入口の作りを変えたら、同じPRでこの資料も直す。

---


パレットの表示では、アクション表の分類を日英のタイトルの先頭に一段だけ付ける（RFN01-114）。たとえば「ファイル: 名前を付けて保存…」。入力前はカテゴリ順、検索時は一致度順、同点はカテゴリ順とする。表示された一致箇所を強調する。操作IDと共通のTitleはそのまま使い、カテゴリ付きの文字列はパレットで組み立てる。

## 1. 方針

1. **操作には名前が1つ**：同じ操作は、どの入口から押しても同じ名前（`Command`）で呼ぶ。入口ごとに別の名前・別の処理を持たない。
2. **アクションの表が1つ**（RFN01-114）：操作ごとに、変わらないID・Title・Description（日本語・英語）・既定のキー・分類を `src/actions.rs` の表の1行に持つ。タイトルバーのメニューの行の名前、コマンドパレット、設定のKeys、キーの割り当ての保存（IDで書く）がこの表を読む。名前を入口ごとに書かない。
3. **前提の答えは1か所**：その操作がいま実行できるか（前提）は、`Scene::enabled(Command)` だけが答える。メニューを灰色にするのも、パレットに並べないのも、キーで断るのも、この答えを読む。
4. **入口は1つ**：どの入口も `menu_commands::run` を通る。`run` は**実行の直前に**、対象がまだ同じかと前提を確かめ、満たせば実行する。灰色にした・並べなかったことに頼らない（開いてから押すまでに場面が変わることがある）。
5. **同じ働きは同じ関数**：入口が違っても同じ働きなら、Rustの同じ関数を呼ぶ。Slintの側に判断を書かない（Slintは見た目と、Rustへの合図だけ）。

## 2. 部品

共通の実行処理は `src/menu_commands.rs` に置く。

| 部品 | 役割 |
| -- | -- |
| `Command` | 操作の名前。タイトルバーのメニューの行、キー、パレット、⋮・右クリックの行が、みなこれに落ちる |
| `actions::all()`（`src/actions.rs`） | **アクションの表**。1行＝ID（例 `file.save`。保存に使うので変えない）・Title・Description（日本語・英語）・既定のキー・キーが固定か・分類（Keysの見出し）・場面（窓／Quick Draft／ファイルツリー）・`Command`。挿入の形は挿入メニューの表から作る（IDは形の名前 `insert.edit-ruby` など） |
| `Target` | 操作の対象（ペインとTAB、入力欄、Terminalの上段・下段、ファイルツリー）。メニュー・パレットを開いたときやキーを押したときに捕まえ、実行時に照合する |
| `Scene` | 対象の場面を一度だけ読んだもの（本文を出しているか、書き換えられるか、ファイルがあるか、Terminalか、選択があるか…）。手間のかかるもの（バックアップの有無・Gitの管理下か・いまの行に置けるもの）は問われたときに読む |
| `Scene::enabled(Command)` | **前提の答え**。操作ごとに1行。言葉の意味は一覧の4.1 |
| `run(window, live, target, command, name)` | **入口**。対象を確かめ、前提を確かめ、`execute` する。断ったときは `name` で「この場面では使えません」と知らせる（`quiet` の操作は黙る） |
| `execute` | 実行そのもの。`run` からだけ呼ぶ |
| `quiet(Command)` | 押せない理由が**場所ではなくその時の状態**の操作（戻す履歴が無い、隣のPaneが無い、倍率の端、貼るKillが無い、スペルチェック中でない）。押すたびに知らせると煩いので黙る |
| `Item` | タイトルバーのメニューの中身（Windowsのメニューにする前の形）。`build` が組み、`native` がWindowsのメニューにし、パレット（`menu_snapshot`）は中身をそのまま読む |

## 3. 入口ごとの道

| 入口 | 道 |
| -- | -- |
| タイトルバーのメニュー | `build`（行の名前は `act!` で表から、押せるかは `Scene::enabled`）→ `native` → 選ばれた行 → `run` |
| コマンドパレット | 表の行（いま押せるものだけ、`allowed_for`）とデータの行（最近のフォルダ・単語チェックのモード・シェル・テンプレート）。1行目にTitle、2行目にDescription。選ばれた行 → `run` |
| キー | `shortcuts::resolve` が押されたキーを表の行（位置）へ → `run_command` → `key_command` で `Command` へ → `run` |
| ⋮・TABの右クリック・TAB帯の右クリック・本文の右クリック | 行は `MenuAction`（Slintの列挙）で操作を名指しする。開く直前に `MenuActions.refresh()`（対象を捕まえる）、行の灰色は `MenuActions.allowed`（`Scene::enabled` を読む）、押されたら `MenuActions.run` → `menu_action_command` で `Command` へ → `run` |
| 書式のツールバー・書式パレット | `run_format` → `run` |
| Explorer・Workspaceのファイルツリー | 見出しの釦・右クリック・ツリーにフォーカスがあるときのキー・パレット → `Command::Tree` → `run` |

ファイルツリーは表示中の面、Workspace、ルートの一覧、選択したパスを対象として持つ。右クリックではクリックした行、パレットでは開いた時点の選択を使う。キーの場面はSlintのフォーカスで選び、Enter・Delete・矢印キーを単独で割り当てられるのはこの場面に限る。登録フォルダ自体の名前変更・複製・削除は `Scene::enabled` から共通の条件で防ぐ。

**例外**（`Command` を通らないもの）

* Quick Draftの本文の右クリック：Quick Draftの本文に効く別の道（文書のペインが対象ではない）。
* 貼り付けの右クリック：欄を通して貼る道（IMEと同じ道を通すため）。押せるかだけ `Scene::enabled` を読む。
* 背景・TAB見出しの色・外観の右クリック：開く位置を画面の側が知っているので、開く処理は画面の側。押せるかだけ `Scene::enabled` を読む。
* 左ペイン・設定・パレット・下段のTABの操作（`run_shortcut` の前半）：文書の対象を持たない。
* 面の中の釦（Workspaceの管理、Git・比較・印刷プレビュー・設定の画面など）は、RFN01-115の後続範囲で検討する。

## 4. データで中身が変わる項目

書き手のデータの数だけ行が増える項目（最近のフォルダ・テンプレート・単語チェックのモード・登録したシェル）は、表に1行ずつ載せない。**汎用のアクションを1つ持ち、キーはそこに割り当てる**。実行するとデータを読み、パレットに選ぶ一覧を出す（`command_palette::open_list`）。

| 汎用のアクション | 選ぶ一覧 |
| -- | -- |
| テンプレートから新規…（`file.new-from-template`） | テンプレート |
| 最近のフォルダを開く…（`file.recent-folder`） | 最近のフォルダ |
| 単語チェックのモードを選ぶ…（`edit.word-mode`） | 単語チェックのモード |
| 新しいTerminal（シェルを選ぶ）…（`file.new-terminal-pick`） | 登録したシェル |

個々の行は、パレットで操作を探したときにも出る（キーは割り当てられない）。倍率の刻み（50%〜240%）は表に載せず、パレットにも出さない。

## 5. 同じ働きは同じ関数

入口が複数ある働きは、Rustの1つの関数にまとめる。

| 働き | 関数 | 入口 |
| -- | -- | -- |
| フォルダ内を検索・置換 | `open_folder_search(replace, folder)` | Ctrl+Shift+F／Ctrl+Shift+H、タイトルバー、Explorer・Workspaceの見出しの🔍（`toggle_tree_search`）、木の右クリック「このフォルダを検索」（フォルダを渡す）、左ペインの欄でのキー |
| 現在の文書を木で表示・すべて畳む・更新 | `explorer_command` | Explorerの見出しの釦、Workspaceの切り替えメニュー |
| 木の新規作成・名前の変更・複製・削除など | `tree_command` | Explorerの見出しの「New」、木の右クリック |

新しい入口を作るときは、まずこの表と一覧（[設定とアクションの一覧.md](設定とアクションの一覧.md) の2章）で、同じ働きが既にあるかを数える。

## 6. 新しいアクションを足す手順

1. 一覧の2章で、同じ働きが既に無いかを確かめる。
2. `Command` に名前を足す。
3. **アクションの表（`src/actions.rs`）に1行足す**：ID（`分類.名前`、一度決めたら変えない）、Title・Description（日本語・英語）、既定のキー（無ければ空）、分類。
4. `Scene::enabled` に前提を1行足す（一覧の4.1の言葉で書けるように）。その時の状態だけで押せない操作なら `quiet` にも足す。
5. `execute` に実行を足す。既存の働きなら、その関数を呼ぶ。
6. 入口を足す（キーとパレットは表に載せれば出る）：
   * タイトルバーのメニュー：`build` の分類に `act!(Command::…)` で1行（名前も押せるかも書かない）。
   * ⋮・右クリック：`MenuAction` に名前を足し、`menu_action_command` で `Command` へ。行は `enabled: MenuActions.allowed(…)`、`activated => { MenuActions.run(…); …close(); }`。
7. 一覧（設定とアクションの一覧.md）の2章・4章を直す。
8. 試験：前提を満たすとき走り、満たさないとき走らないことを `run` で確かめる。

## 7. 経緯

* 2026-11-05 以前：前提はタイトルバーのメニューを組む処理の行ごとに書かれ、⋮・右クリックは `.slint` の中に別の条件（`if root.writing` など）、キーは前提を確かめずに実行先へ渡し、パレットはメニューを組んで結果を借りていた（1回36ミリ秒）。キーの実行は `shortcuts::run_command` に別の表があった。
* RFN01-66 第2弾：`Scene::enabled` に集め、メニューの中身（`Item`）とWindowsのメニュー（`native`）を分け、キー・パレット・⋮・右クリックが同じ答えを読むようにした。
* RFN01-66 第3弾：入口を `run` の1つにし（実行の直前に確かめる）、キーの表を外して `Command` に落とし、フォルダ内の検索を `open_folder_search` の1つにした。
* RFN01-114：アクションの表（`src/actions.rs`）を作った。名前の表（`NAMES` など）と `ShortcutAction` を外し、キーの割り当てはIDで保存する（4までの番号の保存は読むときに一度だけ移す）。パレットは表から並べ、2行目にDescriptionを出す。
