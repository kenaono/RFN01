# RFN Edit のテスト

## WSL で共通ロジックを確認する

UbuntuのWSLにRustとCargoを入れ、リポジトリのルートから実行する。初回はCargoが使えることを `cargo --version` で確認する。

```sh
cargo test --locked --offline --manifest-path Test/wsl/Cargo.toml --target-dir target/wsl-tests
```

この入口はアプリ本体と同じRustソースを読み、行・文字の差分、Gitのグラフ、キルリング、ペインの配置、本文のブロック解析、Workspaceのパス境界を検証する。WSLではLinuxのシンボリックリンクを使った境界テストも走る。追加のCargo依存はない。

## Windows でアプリ全体の Cargo テストを実行する

`cargo test --locked --offline` を基本とする。並列度はリポジトリ設定の4本を使う。

| 領域 | 要件定義の参照先 | 自動テストで区別すること |
| --- | --- | --- |
| 本文・Markdown | 4章、7.1〜7.9 | 文字位置・取り消し・行の解析と、実際の編集操作による表示更新を別に確認する |
| ファイル・復旧・Workspace | 5章、8.1〜8.6 | 文字コード・改行、パス境界、保存とバックアップ、失敗時の元データ維持、再起動後の復元を確認する |
| 編集画面と操作 | 6章、11章、アクションの仕組み | アクションの前提、押下後に対象が変わる場合、ボタン・キー・パレットの配線を確認する。保存済みの旧形式も互換性として扱う |
| 検索・リンク・索引 | 7.7、追加要件 | 検索条件、文書の開閉や編集状態、索引更新と対象切替、リンク先が存在しない場合を確認する |
| 描画・IME・印刷 | 6.3、7.3〜7.5、7.10 | 組版・カーソル位置・印刷ページは自動で、IME変換候補やWindowsのダイアログとの往復は実画面で確認する |
| Git・比較 | 7.11、8.7〜8.9 | 一時リポジトリでGitの操作と履歴を検証し、差分計算・表示・反映先の検証も分ける |
| Terminal・Quick Draft | 6.8、11.7、12章 | 端末データの解析やキーの変換と、ConPTYやWSLで実際にシェルを起動するケースを分ける |
| 設定・診断 | 9章、11.8、16章 | 設定の保存と旧形式の読み込み、取り込み失敗時の維持、診断ログの内容・保持・異常時の記録を確認する |

毎回実行するテストには、一時ファイルやオフスクリーンで安定して判定できるものを置く。Explorerの右クリックメニューと更新抑止のテストもここに含める。

`cargo test --locked --offline -- --list` で一覧を、`cargo test --locked --offline -- --ignored --list` で通常は除外する一覧を確認できる。描画スナップショットや計測、本物のシェル・WSL・印刷を使うケースは、目的に合うテスト名を指定して個別に実行する。アプリからWSLを起動する試験はWindows側で実行する。DirectWrite、WindowsのCP932変換、ConPTY、ジャンクションなどもWindows側で確認する。印刷ジョブを実際に出すテストは、利用する出力先を確認してから実行する。Windowsの音声合成・再生を使う読み上げのテストは、日本語音声が入っている環境で個別実行する。音声の有無の判定と速度設定の互換性は通常テストに含む。

```powershell
cargo test --locked --offline read_aloud_tests:: -- --ignored --test-threads=1
```

## Windows の実画面で確認すること

- [Windows実画面のシナリオ](RFN01-116_Windows実画面.md)で、Windowsのファイルダイアログ、IME、印刷ダイアログとの境界を確認する。
- [ファイルツリーのフォーカス](RFN01-115_ファイルツリーのフォーカス.md)で、連続したキー操作と確認画面からの復帰を確認する。

Windows実画面、実際の印刷、外部ツールを起動する確認は、それぞれの前提を満たす環境で個別に実行する。

結果はシナリオ名、対象の実行ファイル、環境（Windows・IME・プリンターのうち関係するもの）、結果（成功／失敗／未実施）、失敗した操作を記録する。期待結果まで観察したケースを成功とする。
