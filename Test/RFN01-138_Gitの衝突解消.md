# RFN01-138 Gitの衝突解消

試験用リポジトリをWorkspaceに登録する。共通のコミットから分岐し、両方のブランチで同じ行を変更したファイルと、片方で変更しもう片方で削除したファイルを用意する。

1. Git RepositoryからMergeする。衝突が起きた後も作業ファイルにマーカーがあり、Git ChangesとGit Repositoryに「Mergeの解消を開く」が出る。
2. ボタンまたはCtrl+Shift+Pのコマンドパレットで解消画面を開く。ファイルを選び、共通祖先・現在側・取り込み側・作業中の結果がそれぞれの内容と一致することを確認する。片側削除のファイルでは削除側に版がないことを確認する。
3. 「解消結果を編集」で文書タブを開き、衝突部分を編集する。保存前に解消画面へ戻ってStageを試し、索引と未保存文書が変わらないことを確認する。保存後はパレットの「解消結果をStage」でStageする。衝突マーカーを残した場合はStageが止まることも確認する。
4. 片側削除のファイルで削除を採用し、確認ダイアログを経て削除がStageされることを確認する。すべての衝突を解消したら「Mergeを続行」を実行する。Gitでマージコミットの親、本文、削除と未解決パスの有無を確認する。
5. 別の試験用リポジトリでTerminalからMergeを始め、アプリを再起動する。途中状態を開き「Mergeを中止…」を選ぶ。対象リポジトリと解消結果への影響が示されることを確認し、取り消しと中止の両方を確認する。
6. マージ方式のPullと、解消画面を開いたままTerminalで対象パスをStageした場合も試す。更新後に未解決一覧と続行の可否がGitの状態に追従する。
